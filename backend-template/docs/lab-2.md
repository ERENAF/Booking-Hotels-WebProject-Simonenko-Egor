Появляется вторая сущность своей темы, связанная с главной как один ко многим, с вложенным маршрутом `/api/<главные>/{id}/<связанные>`: создание и список. ## contract.json: что добавить

```json
{
  "text_field": "title",
  "search": { "param": "q", "field": "title" },
  "child": {
    "resource": "loans",
    "create": { "reader": "Иванов", "taken_at": "2026-10-01" },
    "parent_field": "book_id"
  },
  "rule": {
    "description": "Нельзя выдать книгу, если все экземпляры на руках",
    "parent": { "copies": 1 },
    "setup": [{ "method": "POST", "path": "/api/books/{id}/loans", "body": { "reader": "Иванов", "taken_at": "2026-10-01" } }],
    "violate": { "method": "POST", "path": "/api/books/{id}/loans", "body": { "reader": "Петров", "taken_at": "2026-10-02" } },
    "expect_status": 409
  },
  "stats_path": "/api/books/stats"
}
```

| Поле | Что писать |
| --- | --- |
| `text_field` | Строковое поле главной сущности, в которое чекер запишет строку с SQL-инъекцией |
| `child.resource` | Имя связанного ресурса из пути: для `/api/books/{id}/loans` это `loans` |
| `child.create` | Правильное тело для создания связанной записи |
| `child.parent_field` | Как называется поле связи в ответе, например `book_id` |
| `search` | Только для ★: параметр поиска и поле, в котором ищется слово |
| `rule` | Только для ★★. Чекер создаёт родителя (поля из `parent` подставляются поверх `create`), выполняет запросы из `setup`, потом запрос `violate` и ждёт `expect_status`. `{id}` в пути заменяется на id созданного родителя |
| `stats_path` | Только для ★★: адрес статистики |

## Вопросы к лабе

1. Зачем бэкенду база данных?
БД нужна для надежного и структурированного хранения данных

2. Что такое первичный ключ?
Primary key - уникальный идентификатор каждой строки. Не может повторяться или быть пустым. Чаще всегоо это автоинкрементное число или длинная уникальная строка

3. Что такое внешний ключ? Где он в проекте?
Foreign Key - ссылка на первичный ключ в другой таблице. Нужен для связи и целостности данных.

4. Что такое связь один ко многим? Пример из своей темы.
One2Many - одна запис в таблице А может быть связана с множеством записей в таблице Б

На один номер из таблицы Room может быть несколько броней из таблицы Booking

5. Что такое SQL-инъекция?
Вредоносный SQL-код который БД может обработать. Приводит к утечке данных/удалению их или обходу авторизации

6. Как защититься от SQL-инъекции?
Параметризованные запросы - замена склейки строк, сервер компилирует структуру SQL запроса, затем безопасно подставляет туда данные строго как текст, а не код.
ORM - современные инструменты по умолчанию используют параметризованные запросы
Валидация и фильтрация

7. Что такое миграция?
Миграция — это «система контроля версий» для структуры вашей базы данных. Это специальные файлы с кодом, которые пошагово описывают изменения в БД: создание новых таблиц, добавление колонок или удаление индексов. Они позволяют разработчикам синхронизировать структуру БД на компьютерах друг друга и безопасно обновлять ее на реальном сервере

8. Зачем файл .env и почему его нет в git?
в файле .env хранятся конфигурационные переменные окружения приложения — секретные ключи, пароли от базы данных, токены сторонних сервисов и порты.

Если секретные ключи попадут в публичный (или даже приватный) доступ на GitHub, злоумышленники смогут угнать базу данных или списать деньги со счетов связанных сервисов. Вместо него в git кладут шаблон .env.example без реальных паролей.

9. Что такое индекс?

Индекс — это специальная структура данных в БД, которая создается для определенных колонок, чтобы категорически ускорить поиск строк. Представьте это как алфавитный указатель в конце толстой энциклопедии. Вместо того чтобы пролистывать всю базу данных целиком (Full Table Scan), БД сразу смотрит в индекс и находит нужную строку за доли секунды.

Минус: индексы замедляют операции записи (INSERT, UPDATE), так как при каждом изменении данных нужно перестраивать и сам индекс.

10. Что такое транзакция?

Транзакция — это группа последовательных операций с базой данных, которая выполняется как одно неделимое целое.

Для транзакций действует правило «все или ничего»: либо все операции внутри нее завершаются успешно (Commit), либо, если произошла хоть одна ошибка, база данных полностью отменяет все изменения и возвращается к исходному состоянию (Rollback).
